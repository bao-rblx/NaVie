# NaVie — Algorithms (graded core)

All algorithms live in `backend/navie/search/` (plus `traffic/`, `logistics/`) and are written by the team. Library implementations (networkx, pgmpy, Valhalla) are allowed **only in tests** as oracles.

## 1. Graph model
- Nodes: OSM intersections after simplification. Edges: directed road segments.
- Storage: CSR arrays in `.npz` — `node_lat`, `node_lon` (float64), `indptr`, `indices` (int32), and per-edge arrays `length_m`, `road_class` (uint8), `maxspeed_kmh`, `oneway`, `flags` (bit mask: motorway, motorcycle_no, toll, footway, bridge), `maxweight_t`, `maxheight_m`, `name_id`.
- Reverse graph (transposed CSR) built at load time for bidirectional search.
- Mode profile = function `(edge) -> allowed: bool, speed_kmh: float`. Profiles in `graph/profiles.py`:

| Mode | Allowed | Free-flow speed |
|---|---|---|
| walk | all except motorway/trunk without sidewalk; ignores oneway | 4.8 km/h |
| motorbike | not motorway, not `motorcycle=no` | min(maxspeed, class default) × 0.9 |
| car / taxi | not footway/path, respects oneway | min(maxspeed, class default) |
| truck | car rules + `maxweight ≥ load`, `maxheight ≥ 4.0 m`, truck-ban window (C) | min(maxspeed, 60) |

- Edge cost `w(e, t) = length_m / speed(e, t)` for `weight="time"`, or `length_m` for `"distance"`. `speed(e, t)` comes from the traffic model (§4).

## 2. Search algorithms
Common interface (`search/base.py`):
```python
class SearchResult(TypedDict):
    path: list[int]            # node ids, empty if no path
    cost: float
    nodes_expanded: int
    runtime_ms: float
    peak_memory_kb: float      # tracemalloc
    explored: list[int]        # expansion order (for visualization)

def search(graph, source: int, target: int, cost_fn, heuristic=None, **kw) -> SearchResult
```

| Algorithm | File | Key details | Complete / optimal |
|---|---|---|---|
| UCS (Dijkstra) | `ucs.py` | binary heap (`heapq`), lazy deletion | yes / yes |
| Greedy best-first | `greedy.py` | priority = h(n) | no (graph: yes with closed set) / no |
| A* | `astar.py` | f = g + h, closed set, tie-break on larger g | yes / yes if h admissible |
| Weighted A* | `astar.py` (`w` param) | f = g + w·h, w ∈ {1.2, 1.5, 2, 3} | yes / cost ≤ w·C* |
| Bidirectional Dijkstra | `bidir.py` | alternate frontiers; stop when `top_f + top_b ≥ μ` | yes / yes |
| Bidirectional A* | `bidir.py` | consistent average potentials (Ikeda et al.) | yes / yes |
| IDA* | `ida_star.py` | iterative deepening on f; path-cycle check; node budget cap (e.g. 2M) to avoid hang | yes / yes (slow on big graphs — **that is a finding**) |
| ALT | `alt.py` | 8–16 landmarks (farthest selection), triangle-inequality heuristic, precomputed per mode | yes / yes |
| Replan A* | `replan.py` | restart from current node when edge costs change | yes / yes |
| D* Lite (C) | `dstar_lite.py` | incremental replanning, Koenig & Likhachev 2002 | yes / yes |

Heuristics:
- Distance weight: haversine(n, target).
- Time weight: haversine / v_max, where v_max = max free-flow speed in the profile → admissible.
- Document why the heuristic is admissible and consistent in the essay.

## 3. Correctness tests (must pass)
- Tiny hand-made graphs in `tests/fixtures/` (line, grid, diamond, disconnected, zero-cost edge, negative check rejected).
- For 200 random OD pairs on the HCMC graph: UCS, A*, Bidir, ALT, IDA* (small subgraph) cost == networkx Dijkstra cost (±1e-6).
- Weighted A*: cost ≤ w × optimal.
- Greedy: returns a valid path (edges exist, mode-allowed).
- Property tests (hypothesis): random small graphs.

## 4. Traffic model — Bayesian Network (Category 3 depth)
Structure (`data/traffic/bn_structure.yaml`):
```
TimeOfDay ─┐
DayType ───┼─► Congestion ─► SpeedFactor
Weather ───┤        ▲
RoadClass ─┘   Incident
```
- Variables (discrete): TimeOfDay {night, morning_peak, midday, evening_peak, evening}, DayType {weekday, weekend, holiday}, Weather {dry, light_rain, heavy_rain}, RoadClass {primary, secondary, tertiary, residential}, Incident {none, minor, blocking}, Congestion {free, moderate, heavy, jammed}, SpeedFactor {1.0, 0.7, 0.45, 0.2}.
- Parameters learned by maximum likelihood with Laplace smoothing from `simulated_observations.csv` (generated by `scripts/simulate_traffic.py` with documented assumptions; real test-drive data added if collected).
- Inference: own **variable elimination** + **enumeration** (`traffic/bn.py`); Gibbs sampling as stretch, compared on accuracy vs runtime.
- Use: expected SpeedFactor `E[SF | evidence]` multiplies free-flow speed per edge. Cache by `(time_bucket, day_type, weather, road_class, incident)` → only ~900 combinations, so no per-edge inference cost.
- Tests: match pgmpy within 1e-6; CPTs sum to 1.

## 5. Dynamic obstacles & rerouting
- Incident → affected edges within 50 m (spatial grid index) → `blocking` sets cost = ∞, others pass `Incident` evidence to BN.
- Driver session: on incident change, server checks whether active route uses an affected edge → runs Replan A* (or D* Lite) from current node → if new ETA better by ≥ 2 min or route blocked, push `faster_route`.
- Experiment: Replan A* vs D* Lite — nodes expanded per replan as obstacles appear along the route.

## 6. Multimodal intercity
- Hub graph: nodes = hubs (stations, airports, bus terminals, ports) + origin + destination. Edges = road legs (access/egress via city graph or road-skeleton estimate) + scheduled services (time-expanded: one edge per departure).
- Multi-criteria label-setting search over (arrival time, cost, transfers) → Pareto set (dominance pruning). Max 3 transfers.
- Transfer penalties: airport check-in 90 min before departure, train 30 min, coach 20 min, ferry 30 min.

## 7. Logistics local search
- Distance matrix between stops from many-to-many Dijkstra (one UCS per stop on the road graph).
- TSP ordering: nearest neighbour (baseline), brute force (n ≤ 9, ground truth), Hill Climbing (2-opt neighbourhood, random restarts), Simulated Annealing (2-opt + or-opt moves, geometric cooling `T ← αT`, α ∈ {0.95, 0.99, 0.995}).
- VRP (C): k vehicles with capacity; SA with relocate/swap moves between routes; penalty for capacity violation.
- Multi-agent extension (C): route k vehicles sequentially, adding a congestion penalty on edges already used by earlier agents; compare total fleet time with/without.
